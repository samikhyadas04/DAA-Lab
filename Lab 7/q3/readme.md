# Tower of Hanoi with 4 Pegs (Frame–Stewart Algorithm)

## 1. Problem

8 disks of different sizes start on peg 1, largest at the bottom. There are
**4** pegs. Move one disk at a time, never place a larger disk on a
smaller one, and move all 8 disks to another peg. Solve it in **33**
moves, and generalize to `n` disks.

## 2. Algorithm: Frame–Stewart

With only 3 pegs the classic recursive algorithm needs `2^n − 1` moves.
With a 4th peg available we can do dramatically better by *parking* a
group of disks out of the way on the extra peg while we shuttle the rest
with plain 3‑peg Hanoi.

```
FrameStewart(n, src, aux1, aux2, dst):
    if n == 0: return
    choose split point k  (0 <= k < n)      # picked by DP, see below
    FrameStewart(k, src, dst, aux2, aux1)   # move top k disks out of the way
                                             # onto aux1, using all 4 pegs
    Hanoi3(n-k, src, aux2, dst)             # move remaining n-k disks with
                                             # classic 3-peg Hanoi (aux1 is
                                             # occupied, so unusable here)
    FrameStewart(k, aux1, src, aux2, dst)   # bring the k parked disks onto
                                             # dst, again using all 4 pegs
```

`Hanoi3(m, src, spare, dst)` is the textbook 3-peg algorithm and costs
`2^m − 1` moves.

### 2.1 Choosing the split point k

The **optimal** `k` for each `n` is *not* guessed or hard-coded — it is
computed by dynamic programming:

```
f(0) = 0
f(m) = min over k in [0, m) of  2*f(k) + (2^(m-k) − 1)     for m = 1..n
```

`f(m)` is the optimal move count for `m` disks on 4 pegs, and the
minimizing `k` is stored so `FrameStewart` knows exactly where to split at
every level of the recursion. (This DP is the reason the algorithm is
fully general in `n`, not just tuned for `n = 8`.)

### 2.2 Why 33 moves for n = 8

Running the DP gives split points `k(1..8) = 0,0,1,1,2,3,3,4` and
`f(8) = 33`, matching the well-known optimal value for 4-peg Hanoi with 8
disks. (Optimality of the Frame–Stewart numbers for the 4-peg case was
long conjectured and was proved in general by Bousch in 2014; the DP here
reproduces the numbers constructively and the program cross-checks the
count generated by the actual recursive algorithm against it.)

## 3. Complexity

* **DP precompute** of `f(1..n)` and the optimal split points:
  `O(n²)` time (for each `m`, try every `k < m`), `O(n)` space.
* **Move generation:** the algorithm produces exactly `f(n)` moves; for 4
  pegs this grows *sub-exponentially*, `f(n) = Θ(2^{√(2n)})`, far below the
  `Θ(2^n)` of the 3-peg case. Generating and printing the sequence takes
  time linear in its own length, `O(f(n))`.

## 4. Input representation

The program takes one command-line integer `n` (number of disks, default
8, max 40 in this implementation). Pegs are represented simply as indices
`0..3`; each peg is modelled internally as a stack (array + height) of
disk sizes for validation purposes.

## 5. Validation program (`hanoi4.c`)

For the given `n` the program:
1. Runs the DP to get the optimal move count `f(n)` and split points.
2. Runs `FrameStewart` to actually generate the move list.
3. **Replays every move** against an explicit 4-peg model, checking at
   each step that (a) only the top disk of the source peg is moved, and
   (b) it is never placed on a smaller disk — i.e. full legality of the
   *entire* move sequence, not just the final state.
4. Checks that all `n` disks end up on the target peg in correctly sorted
   order and that no disks are left behind on any other peg.
5. Cross-checks that the number of moves actually generated equals the
   DP-predicted optimum `f(n)`.
6. Prints a summary table of `f(1..16)` (or up to `n` if larger) for
   context, reproducing the classical Frame–Stewart numbers
   `1, 3, 5, 9, 13, 17, 25, 33, …`.

## 6. Build & run

```sh
gcc -O2 -Wall -Wextra -o hanoi4 hanoi4.c
./hanoi4       # n = 8 (default) — the original problem
./hanoi4 12    # generalizes to n = 12 disks
```
